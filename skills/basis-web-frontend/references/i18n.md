# i18n — externalização de texto em app Thymeleaf

Complementa o §6 da skill. Aqui está a convenção completa, o comportamento do inlining
medido no Thymeleaf 3.1.5 e o checklist de revisão.

## Convenção de nome de chave

`<entidade>.<elemento>.<propriedade>` — a entidade é a tela ou o agregado, o elemento é
*onde* o texto aparece, a propriedade é *qual* texto é.

```properties
# ---- comum: repete IDÊNTICO entre entidades, confirmado no código ----
comum.acao.editar=Editar
comum.acao.excluir=Excluir
comum.acao.cancelar=Cancelar
comum.botao.salvar=Salvar alterações
comum.tabela.acoes=Ações
comum.paginacao.registros={0}–{1} de {2} registros
comum.paginacao.vazio=nenhum registro

# ---- app: sem entidade específica (menu, rodapé, banner global) ----
app.menu.funcionario=Funcionários
app.grupo.cadastros=Cadastros
app.botao.sair=Sair
app.rodape.copyright=© {0} Basis Tecnologia
app.erro.semPermissao=Você não tem permissão para esta ação.

# ---- entidade ----
funcao.titulo=Funções
funcao.subtitulo=Cargos e funções que podem ser atribuídos aos funcionários desta empresa.
funcao.legenda.nova=Nova função
funcao.campo.descricao=Descrição
funcao.tabela.descricao=Descrição
funcao.botao.criar=Criar função
funcao.excluir.confirmacao=Excluir esta função?
funcao.lista.vazia=Nenhuma função cadastrada.
```

Elementos que se repetem entre telas e valem como vocabulário: `titulo`, `subtitulo`,
`legenda`, `campo`, `botao`, `acao`, `tabela`, `lista`, `status`, `paginacao`, `menu`,
`grupo`, `rodape`.

### As três regras que não são óbvias

**Chave própria por elemento, mesmo com texto igual hoje.** `funcao.campo.descricao` e
`funcao.tabela.descricao` valem "Descrição" as duas. Fundi-las economiza uma linha e cobra
depois: no dia em que o label do formulário virar "Descrição do cargo", o cabeçalho da
tabela vai junto, e quem mexeu não tinha como saber.

**`comum.*` só com repetição confirmada.** Confirmada quer dizer: o mesmo texto já aparece em
duas entidades no código, não "provavelmente vai aparecer". Chave `comum` criada por
antecipação vira acoplamento entre telas que nunca se pareceram de fato.

**Nunca o idioma na chave.** `funcao.botao.criar.pt` fecha a porta: acrescentar inglês
passaria a exigir renomear todas as chaves e todos os templates. O idioma é o **arquivo**
(`messages.properties`, `messages_en.properties`), nunca a chave.

### O que fica de fora, de propósito

| Não vira chave | Por quê |
|---|---|
| Nome do produto e marca ("Basis Ponto", "Basis") | Nome próprio, não se traduz |
| Mensagem vinda do Java (`${erro}`, `${sucesso}`, exceção de negócio) | Outra camada — quem resolve é o `MessageSource` no serviço/controller, não o template |
| Dado do banco renderizado (`${f.nome()}`) | É dado, não rótulo |

## Texto em atributo

O ponto que mais escapa, porque a tela fica visualmente correta com o texto ainda no HTML.

```html
<input th:placeholder="#{login.campo.emailPlaceholder}" placeholder="seu@email.com">

<button th:hx-confirm="#{funcao.excluir.confirmacao}"
        th:text="#{comum.acao.excluir}">Excluir</button>

<button th:title="#{app.botao.recolherMenu}" title="Recolher menu">…</button>
```

Manter o atributo estático ao lado do `th:` é intencional: é o que a página mostra quando
aberta direto do disco, sem o servidor, e serve de documentação do texto esperado.

## Inlining em `<script>` — os quatro comportamentos, medidos

Thymeleaf 3.1.5, template em modo HTML, variável `v` valendo `a "b" <c> & d` com uma quebra
de linha.

| | Sem `th:inline` | Com `th:inline="javascript"` |
|---|---|---|
| `var x = [[${v}]];` | `var x = a &quot;b&quot; &lt;c&gt; &amp; d` + quebra de linha crua — entidade HTML dentro do JS e sintaxe quebrada | `var x = "a \"b\" <c> & d\ne";` — literal JS válido |
| `const t = /*[[#{k}]]*/ 'padrão';` | `const t = /*Excluir*/ 'padrão';` — **o valor entra no comentário e o código segue usando `'padrão'`** | `const t = "Excluir";` |
| `` `<span>[[#{k}]]</span>` `` | valor cru, sem aspas | `` `<span>"Excluir"</span>` `` — as aspas do literal JS aparecem na tela |
| `` `<span>[(#{k})]</span>` `` | valor cru, sem aspas | `` `<span>Excluir</span>` `` — é esta a forma para dentro de string |

Três conclusões:

1. **`th:inline="javascript"` é obrigatório.** Sem ele não há erro nem aviso: `[[ ]]` continua
   sendo substituído, só que com escape de HTML e sem aspas.
2. **A forma `/*[[…]]*/ 'padrão'` só funciona no modo JavaScript.** Sem o atributo, o valor vai
   parar dentro do comentário e a página fica com o literal em português para sempre. Esse é o
   modo de falha que passa em teste de navegador, em revisão e em pipeline verde — aconteceu
   aqui, em três templates de uma vez.
3. **Dentro de string, `[( )]`; sozinho, `[[ ]]`.** `[[ ]]` devolve o literal já entre aspas.

```html
<script th:inline="javascript">
    const msgSemPermissao = /*[[#{app.erro.semPermissao}]]*/ 'Você não tem permissão para esta ação.';
    const textoFechar     = /*[[#{app.botao.fechar}]]*/ 'Fechar';

    alvo.querySelector('span').textContent = msgSemPermissao;
</script>
```

Prefira `textContent` a montar HTML por concatenação: além de não precisar decidir entre
`[[ ]]` e `[( )]`, é o que impede que um texto de mensagem com `<` quebre a marcação.

### Antes disso, confira se o `<script>` renderiza

Página que usa o layout entrega só `~{::section}`. `<script>` irmão da `<section>` — o lugar
onde o hábito de HTML manda pôr — é descartado sem erro e sem log. `th:inline` impecável num
bloco que não renderiza não serve para nada. Ver §3 da skill.

## Configuração

```yaml
spring:
  messages:
    basename: messages
    encoding: UTF-8
    fallback-to-system-locale: false
```

- **`encoding: UTF-8`** — sem isto o acento vira caractere estranho na tela.
- **`fallback-to-system-locale: false`** — sem isto, no dia em que existir
  `messages_en.properties`, um pod cujo locale o cluster definiu como inglês passa a responder
  em inglês para todo mundo. O locale do contêiner não é decisão da aplicação, e o sintoma
  aparece em produção, não em dev.

O arquivo base é sempre `messages.properties`, sem sufixo de locale. `messages_pt_BR.properties`
sozinho não resolve para locale nenhum que não seja exatamente `pt_BR`.

## `MessageFormat` — só nas mensagens com parâmetro

Mensagem sem argumento é devolvida crua. Assim que há argumento, ela passa por
`MessageFormat`, e duas coisas mudam:

**Número é formatado no locale.**

```properties
comum.paginacao.registros={0}–{1} de {2} registros
```

`1234` sai `1.234` — desejável na contagem, errado em ano, matrícula ou identificador. Passe
esses já convertidos para texto:

```html
<!-- certo: 2026 -->
<p th:text="#{app.rodape.copyright(${#calendars.format(#calendars.createNow(), 'yyyy')})}">…</p>
```

Um `int` de ano no lugar sairia `2.026`.

**Aspa simples é caractere de escape.** Em mensagem com parâmetro, `'` solto some ou muda o
sentido do que vem depois; para exibir uma aspa, dobre (`''`). Mensagem sem parâmetro não
sofre isso — o que torna o defeito intermitente e difícil de atribuir.

## Checklist de revisão

- [ ] Nenhum texto visível cravado no template — inclusive em `th:title`, `th:placeholder`, `th:alt`, `th:hx-confirm`
- [ ] Todo `<script>` com `#{...}` tem `th:inline="javascript"` na tag
- [ ] Todo `<script>` de página está **dentro** da `<section>`
- [ ] `[( )]` onde o valor entra numa string; `[[ ]]` onde ele é o valor inteiro
- [ ] Chaves usadas e chaves definidas batem 1:1 — nenhuma faltando, nenhuma órfã
- [ ] Nenhuma chave nova em `comum.*` sem repetição confirmada no código
- [ ] Nenhuma aspa simples solta em mensagem com parâmetro
- [ ] Nenhum número que não deva levar separador de milhar passando como argumento

A conferência de chaves órfãs e faltantes dá para fazer no diff:

```bash
grep -rhoE '#\{[a-zA-Z0-9_.]+' src/main/resources/templates | sed 's/#{//' | sort -u > /tmp/usadas
grep -vE '^\s*#' src/main/resources/messages.properties | grep '=' | cut -d= -f1 | sort -u > /tmp/definidas
comm -23 /tmp/usadas /tmp/definidas   # usadas e não definidas — quebram a página
comm -13 /tmp/usadas /tmp/definidas   # definidas e não usadas — lixo acumulando
```

Chave usada e não definida **não** levanta exceção e não gera log: o Thymeleaf escreve
`??funcao.titulo_pt_BR??` na tela e segue em frente. Compila, sobe, passa em pipeline verde e
chega ao usuário como texto quebrado — só é pega por quem abrir aquela tela. Daí valer rodar
o `comm` antes de abrir a MR, e não confiar que o build reprovaria.
